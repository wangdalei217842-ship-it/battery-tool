# 本地开发 → GitHub → 线上发布

本项目从 2026-11 起改用「本地改 → 推送 GitHub → 服务器拉取」的流程。
线上不再用 scp 直接覆盖文件，避免本地和线上代码版本不一致。

---

## 一、本地开发与调试

**目录**：`D:\vibe\battery-tracker\`

```
双击「启动-仅本机.bat」   → 只在 127.0.0.1 可访问，最安全
双击「启动.bat」          → 监听 0.0.0.0，同一 WiFi 下手机也能连
```

浏览器打开 `http://127.0.0.1:8787`。

本地 `data\` 是**独立的测试库**，和线上数据完全隔离，随便改。

### 改代码后的注意事项

| 改了什么 | 要做什么 |
|---|---|
| `static/app.js`、`style.css` | **必须把 `index.html` 和 `sw.js` 里的 `?v=NN` 改成下一个数字**，否则浏览器用缓存，改了像没改 |
| `server.py`、`store.py` 等后端 | 关掉命令行窗口，重新双击启动 |
| 数据库结构（加表/加字段） | 在 `init_db()` 里写迁移，不要手改线上库 |

## 二、提交到 GitHub

```bash
cd D:\vibe\battery-tracker

git status                  # 先看改了什么
git add -A
git commit -m "feat: 加了什么功能"
git push
```

### 绝对不能提交的东西

`.gitignore` 已经排除，但提交前扫一眼 `git status`：

- `data/` —— 真实账号、报账、药品、测试数据
- `*.db` —— 任何 SQLite 数据库文件
- `admin-password.txt`
- `*.local` —— 含真实 IP/域名的本地副本
- `docs/video/` —— 宣传视频，35MB

**如果误提交了**：

```bash
git rm --cached data/accounts.db
git commit -m "chore: 移除误提交的数据文件"
```

已经推到 GitHub 的话，历史里仍然有，需要 `git filter-repo` 清理，别嫌麻烦——泄露的密码库比返工更麻烦。

## 三、发布到线上

服务器：`<SERVER_IP>`，目录 `/opt/battery-tracker`，服务名 `battery-tracker`。

```bash
# 1. 登录
ssh -i ~/.ssh/<YOUR_KEY> root@<SERVER_IP>

# 2. 拉代码（不碰 data/）
cd /opt/battery-tracker
sudo -u battery git pull

# 3. 重启服务
systemctl restart battery-tracker
systemctl is-active battery-tracker

# 4. 确认没挂
curl -s http://127.0.0.1:8787/api/ping
```

### 发布后必查

```bash
# 服务状态
systemctl status battery-tracker --no-pager | head -12

# 最近错误
journalctl -u battery-tracker -n 30 --no-pager | grep -i "error\|traceback"

# 站点能否打开
curl -s -o /dev/null -w "%{http_code}\n" https://<YOUR_DOMAIN>/
```

## 四、数据备份

**每次发布前**，先在服务器备份一次数据（代码可以回滚，数据不行）：

```bash
cd /opt/battery-tracker
STAMP=$(date +%Y%m%d-%H%M%S)
tar czf /opt/backups/battery-data-$STAMP.tar.gz \
    data/ --exclude='data/backups'
ls -lh /opt/backups/ | tail -3
```

`data/` 里有：
- `accounts.db` —— 账号与会话
- `shared.db` —— 报账 + 药品（全组共用）
- `users/u*.db` —— 每个用户一个独立库
- `uploads/` —— 发票 PDF、方法附件

## 五、出问题怎么回滚

### 代码回滚

```bash
cd /opt/battery-tracker
sudo -u battery git log --oneline -5      # 找到上一个好版本
sudo -u battery git reset --hard <commit>
systemctl restart battery-tracker
```

### 数据回滚

```bash
cd /opt/battery-tracker
tar xzf /opt/backups/battery-data-<时间>.tar.gz    # 覆盖 data/
chown -R battery:battery data/
systemctl restart battery-tracker
```

## 六、常见坑

**改完前端没生效** —— 版本号没升，浏览器用缓存。这是本项目最高频的坑，改 `app.js` 必改版本号。

**登录后跳回登录页** —— 检查 302 响应有没有 `Content-Length: 0`，没有的话 HTTP/1.1 长连接下浏览器会一直等。

**手机上打不开曲线** —— 紧凑卡片（dense）和普通卡片是两套模板，加按钮要两处都加。

**图片/PDF 打不开** —— 检查 `/opt/battery-tracker/data/uploads/` 权限，必须是 `battery:battery`。

**同组通道编号冲突** —— 编号只在同一分组内唯一，跨分组可以重名，这是设计如此。
